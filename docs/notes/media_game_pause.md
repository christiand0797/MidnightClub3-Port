# Cooperative game protection and movie pause — 2026-10-25

The durable coordinator recognizes the actual installed clients `mc3.exe`, `FortniteClient-Win64-Shipping.exe` and `BlackOps3.exe`. Steam and Epic launchers alone do not count as running games. The BO3 addition was confirmed with the real installed client, then tested using temporary fixtures. No game, inference worker or coordinator was started by these tests; physical input is untouched.

Before either media worker launches, a recognized game causes the coordinator to wait. Texture processing retains its existing cooperative batch-boundary stop/restart behavior. Production movie processing now receives a unique private `--pause-file` and the coordinator's `--pause-owner-pid`. On game arrival the coordinator requests a pause while the same movie child stays alive. It checks only game clients inside that live-child loop; waiting for all media workers there would wait on its own child forever. On game exit it removes only its unchanged owned pause marker and the same child resumes its retained decoded frames/encoder.

The video worker limits each NCNN inference invocation to at most eight frames when this protocol is enabled and checks stop/pause between invocations and encoder-feed boundaries. The current invocation finishes; there is no wall-clock pause guarantee. A request does not imply the current GPU batch has already ended, so coordinator state says **pause requested**. The worker holds a read-only Windows synchronization handle to its actual parent; parent death or an invalid owner stops the in-flight movie without resuming GPU work. This leaves the private marker for inspection. The model, weights, source, output dimensions, encoder settings and timing recipe stay unchanged.

User cancellation takes priority over game pause and stays latched even if a stop flag is subsequently removed. It requests the existing private stop, drains the child and preserves user stop files. Explicit stop discards only the current movie's owned temporary work; all already published, authenticated outputs remain intact. A game pause retains current work. Foreign, unreadable or symlinked pause markers are never cleared or overwritten; their appearance requests a cooperative stop before waiting for the child to exit. Unexpected monitoring errors, including malformed progress/inventory or a failed initial child checkpoint, also request that stop. Arbitrary disk/permission failure preventing any stop signal is outside the proven protocol.
